# Решись Авиа — прогноз продаж (блок «Разработка»)

Инструмент превращает CSV-прогноз спроса из ML-части в продукт: ввёл маршрут, дату и цену — получил
число мест, сколько человек захотят купить и прогноз продаж, плюс график распределения спроса по 9 сценариям.

## Что реализовано

| Требование кейса | Где |
|---|---|
| **A.** Скрипт «простое прогнозирование» | `predict.py` |
| **B/C.** Веб-страница с формой, логика на JS | `static/index.html`, `static/app.js` |
| **C.** Backend API, страница отправляет данные через `fetch` | `server.py` (`POST /api/forecast`) |
| Доп. 1. График распределения спроса при введённой цене | SVG-график в `app.js`, PNG в `predict.py --chart` |
| Доп. 2. Регистрация | `POST /api/register` |
| Доп. 3. Авторизация | `POST /api/login`, cookie-сессия; прогноз только для вошедших |
| Доп. 4. Хостинг | **https://gut-server.tail147b9d.ts.net/** (Docker + Tailscale Funnel), см. ниже |

Формула (из условия):

```
желают = 0.5_base_demand − price_sensitivity × (цена − base_price)
купят  = min(seats, max(0, желают))
```

На графике та же формула применяется к каждому сценарию 0.1 … 0.9. Медианный столбец совпадает с числом
«желают» в карточке, красная пунктирная линия — число мест; оранжевым отмечена часть спроса, которая не помещается
в самолёт. Под графиком: 80%-й интервал спроса и в скольких сценариях продажи упираются в места.

## Запуск

Нужен только Python 3.9+ (сторонние библиотеки не используются; matplotlib нужен лишь для `--chart`).

```bash
# веб-приложение (вариант C)
python3 server.py                 # открыть http://127.0.0.1:8000, зарегистрироваться и войти

# скрипт (вариант A)
python3 predict.py Москва Сочи 2026-06-12 9000
python3 predict.py MOW AER 2026-06-12 9000 --chart chart.png

# тесты (формула, ограничения, ошибки ввода, регистрация/вход/выход через API)
python3 -m unittest -v test_app
```

Данные лежат в `data/`: `routes.csv` и прогноз. Если есть `data/my_forecast.csv` (из ML-части), используется он,
иначе — заглушка `data/seasonal_forecast.csv`. Другой файл можно указать в скрипте через `--forecast`.

Города можно вводить кодом (`MOW`, `AER`, `LED`, `KGD`, `OVB`, `MRV`) или названием (`Москва`, `Сочи`, …).
Прогноз есть только для 5 маршрутов из Москвы на 01.06–01.07.2026; на другие маршруты и даты выводится понятная ошибка.

## Хостинг

**Приложение развёрнуто: https://gut-server.tail147b9d.ts.net/** (демо-аккаунт: `jury_demo` / `reshis2026`,
можно и зарегистрироваться самому).

Как развёрнуто: Docker-контейнер на своём сервере (Ubuntu), публичный HTTPS через Tailscale Funnel:

```bash
docker build -t reshis-avia .
docker run -d --name reshis-avia --restart unless-stopped -p 127.0.0.1:8000:8000 -v reshis_avia_state:/app/state reshis-avia
tailscale funnel --bg 8000
```

Без Docker: `python3 server.py --host 0.0.0.0 --port 8080` (или переменные окружения `HOST`, `PORT`).
Пользователи хранятся в `data/users.json` (пароли — PBKDF2-SHA256 с солью), сессии — в памяти процесса.

## API

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| POST | `/api/register` | `{login, password}` | `{login}` + cookie сессии |
| POST | `/api/login` | `{login, password}` | `{login}` + cookie сессии |
| POST | `/api/logout` | — | `{ok: true}` |
| GET | `/api/me` | — | `{login}` или `{login: null}` |
| GET | `/api/routes` | — | маршруты, даты, имя файла прогноза |
| POST | `/api/forecast` | `{origin, destination, date, price}` | места, желают, купят, 9 сценариев |

## Использованные инструменты ИИ

тестов, проверка интерфейса в браузере через Playwright.
